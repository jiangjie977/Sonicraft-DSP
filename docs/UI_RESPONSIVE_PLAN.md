## 一、现状量化（实测统计）

| 文件 | 行数 | 固定 `size(x.dp)` | `weight()` | `BoxWithConstraints` | `maxLines` |
|---|---|---|---|---|---|
| `ui/ScScreens.kt` | 2133 | 12 | 21 | 3 | **3** |
| `ui/MainScreen.kt` | 831 | 0 | 8 | 0 | **0** |
| `ui/components/ScKit.kt` | 697 | 6 | 2 | 0 | **2** |

**结论：全工程 UI 只有 5 处 `maxLines`。** 文本默认自由换行，一旦宽度不足就折成 2~3 行或竖向 1 字宽——这就是 V2408A 截图里崩坏的直接原因。

| # | 位置 | 现象 | 根因 |

## 三、设计原则（为什么不做“按比例缩放”）

1. **内容驱动，不按容器比例缩放。**
   机型名长度差异极大（`NX733J` / `V2408A` / `Pixel 9 Pro XL`），任何 `fillMaxWidth(0.6f)` 都会在某个机型上再次崩。正确做法是「**单行 + 省略**」，让内容自适应而不是容器缩放。
2. **优先保证结构不变，其次才改结构。**
   宽度够 → 保持原横排（本机零变化）；宽度不够 → 才切换堆叠。
3. **三层防线，按顺序生效：**

```
① 文本层：maxLines=1 + Ellipsis（永不折行）
② 布局层：weight 分配剩余空间；不足则按断点切换堆叠
③ 容器层：可滚动 + insets 留白（永不遮挡、永不溢出）
```

4. **禁止在卡片内写死宽度**（如 `Modifier.width(120.dp)` 配长文本），需要限制时用 `widthIn(max = …)`。

---

## 四、断点定义

以**可用宽度 dp**（`BoxWithConstraints.maxWidth`）判定，不看 px、不看机型：

| 断点 | 宽度 | 布局策略 |
|---|---|---|
| `Compact` | `< 360.dp` | 卡片内左右结构 → **上下堆叠**；字号不缩小 |
| `Medium` | `360.dp ~ 480.dp` | 保持横排，文本单行省略（**本机 NX733J 落在此档**） |
| `Expanded` | `> 480.dp` | 保持横排；内容区加 `widthIn(max = 560.dp)` 居中，避免平板拉太长 |

> 断点只在**组件内部**判断，不在页面级判断——这样同一页面可以「设备卡堆叠、列表仍横排」。

## 五、公共能力（先建三个小组件，再改页面）

放在 `ui/components/ScResponsive.kt`：

```kotlin
// 1) 单行文本：任何卡片里的信息行都用它，杜绝折行
@Composable
fun ScTextOneLine(text: String, size: TextUnit, color: Color,
                  modifier: Modifier = Modifier, weight: Float? = null)

// 2) 自适应左右结构：宽度够横排、不够堆叠（本机保持横排）
@Composable
fun ScAdaptiveRow(
    stackBelow: Dp = 360.dp,
    left: @Composable RowScope.() -> Unit,
    right: @Composable RowScope.() -> Unit,
)

// 3) 统一页面容器：处理 insets + 最大宽度 + 滚动
@Composable
fun ScScreenScaffold(content: @Composable ColumnScope.() -> Unit)
```

**收益**：后续所有卡片只改一处调用，不必每个 Composable 手写断点。

## 七、风险

| 风险 | 说明 | 缓解 |
|---|---|---|
| 本机外观发生位移 | 加 `maxLines` 后，本机若文本本来未折行则视觉不变；但 `widthIn` 可能改变胶囊宽度 | 每批改完**截图对比本机**（同页面同滚动位置） |
| 省略导致信息丢失 | 机型名被截断 | 关键信息（机型/系统版本）保留在「我的 → 关于」完整展示 |
| 断点阈值不匹配真机 | 我们只有 NX733J 与 V2408A 两台实机 | 用模拟器覆盖 320/360/411/480dp 四档宽度回归 |
| 引入新组件后风格漂移 | 三个新组件必须复用 `ScColors` / `DesignTokens` | Code Review 只允许取值自 tokens |

## 八、验收判据

| 项 | 判据 |
|---|---|
| 不折行 | 设备卡三行信息、胶囊、统计标签均为单行（可省略） |
| 不竖排 | 任一 `Text` 的渲染宽度 ≥ 2 个字符宽（无 1 字竖排） |
| 不遮挡 | 滚动到底时最后一张卡片完整可见，不被 TabBar 覆盖 |
| 本机零变化 | NX733J 截图与改动前逐像素对比，仅允许「省略号出现」这一处差异 |
| 覆盖机型 | 320 / 360 / 411 / 480dp 四档模拟器 + 两台实机 |
